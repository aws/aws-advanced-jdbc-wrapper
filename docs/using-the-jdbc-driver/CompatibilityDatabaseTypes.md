# Database type compatibility

This document is part of the [Compatibility Guide](./Compatibility.md) and explains plugin compatibility with various database types and deployments. Some plugins require specific metadata from particular database types to function properly. 

For example, the `limitless` plugin is incompatible with [Aurora Global Database](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-global-database.html) because it's built on different architectural principles than [Limitless Database](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/limitless-architecture.html). Aurora Global Database doesn't use transaction routers and doesn't provide the transaction routers' metadata. This lack of required metadata makes it incompatible with the `limitless` plugin.

For Aurora Global Database configuration details, see [Aurora Global Databases](./GlobalDatabases.md).

## Notes

[^1]: Custom endpoints are an Aurora-only feature; this deployment does not support them.

[^2]: On an Aurora Global Database, use the `gdbFailover` plugin. It provides support for cross-region failover.

[^3]: Use `failover`/`failover2` on a single-region cluster. They provide the same coverage with fewer resources. Plugins that begin with `gdb` are designed to be used with global databases.

[^4]: This plugin is designed to only help with Aurora cluster writer endpoints. 

[^5]: Use `readWriteSplitting`/`autoReadWriteSplitting` on a single-region cluster. Plugins that begin with `gdb` are designed to be used with global databases.

[^6]: Use `srw`/`autoSimpleReadWriteSplitting` on a single-region cluster. Plugins that begin with `gdb` are designed to be used with global databases.

[^7]: Limitless is only for Aurora PostgreSQL Limitless DB shard groups. See [Using the Limitless Connection Plugin](./using-plugins/UsingTheLimitlessConnectionPlugin.md).

[^8]: AWS does not support Blue/Green deployments on Aurora global databases or RDS Multi-AZ DB clusters.

[^9]: The plugin needs a multi-instance cluster with discoverable topology; this deployment does not provide one.

[^10]: IAM/Secrets Manager/Okta/ADFS are Amazon RDS/Aurora features; a community database does not support them.

[^11]: Simple Read/Write Splitting needs a reader; a RDS Single-AZ Instance has none.

[^12]: The fastest-response strategy needs multiple readers to choose from; this deployment does not provide them.

[^13]: The initial connection plugin resolves a cluster endpoint to an instance; this deployment has no cluster topology to resolve.

[^14]: Blue/Green deployments are an Amazon RDS/Aurora feature; this plugin does not apply to a community database.
