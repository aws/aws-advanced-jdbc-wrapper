# Database URL types compatibility

This document is part of the [Compatibility Guide](./Compatibility.md) and explains plugin compatibility with various database endpoints.

There are many different URL types (endpoints) that can be used with The AWS Advanced JDBC Wrapper, but certain URL types are not compatible with certain plugins. This page outlines the various URL types and which plugins are compatible with each type.

- [Aurora Global Database Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-global-database-connecting.html) - `<global-db-name>.global-<XYZ>.global.rds.amazonaws.com`
- [Aurora Cluster Writer Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Endpoints.Cluster.html) - `<cluster-name>.cluster-<XYZ>.<region>.rds.amazonaws.com`
- [Aurora Cluster Reader Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Endpoints.Reader.html) - `<cluster-name>.cluster-ro-<XYZ>.<region>.rds.amazonaws.com`
- [Aurora Cluster Custom Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Endpoints.Custom.html) - `<custom-endpoint-name>.cluster-custom-<XYZ>.<region>.rds.amazonaws.com`
- [Aurora Instance Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Endpoints.Instance.html) - `<instance-name>.<XYZ>.<region>.rds.amazonaws.com`
- [RDS Multi-AZ DB Cluster Writer Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/multi-az-db-clusters-concepts-connection-management.html) - `<cluster-name>.cluster-<XYZ>.<region>.rds.amazonaws.com`
- [RDS Multi-AZ DB Cluster Reader Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/multi-az-db-clusters-concepts-connection-management.html) - `<cluster-name>.cluster-ro-<XYZ>.<region>.rds.amazonaws.com`
- [RDS Instance Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/multi-az-db-clusters-concepts-connection-management.html) - `<instance-name>.<XYZ>.<region>.rds.amazonaws.com`
- [RDS Proxy Endpoint](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-proxy-endpoints.html) - `<proxy-name>.proxy-<XYZ>.<region>.rds.amazonaws.com`, `<endpoint-name>.endpoint.proxy-<XYZ>.<region>.rds.amazonaws.com`
- [DB Shard Group Endpoint (Aurora Limitless)](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/limitless-shard.html) - `<shard-group-name>.shardgrp-<XYZ>.<region>.rds.amazonaws.com`
- [IP address](https://en.wikipedia.org/wiki/IP_address) - IPv4 or IPv6 addresses, for example: `8.8.0.0`, `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- User custom domain (CNAME alias) - any other domain names, for example: `my-database.my-domain.com`

## Notes

[^1]: The custom endpoint plugin only applies to an Aurora custom endpoint; on any other endpoint there is no custom-endpoint membership to track.

[^2]: On a cluster endpoint (writer, reader, or global) the IAM token must be generated for the actual instance the connection resolves to. Include the `initialConnection` plugin so the cluster endpoint is resolved to an instance before the token is minted.

[^3]: Limitless only operates on the Aurora PostgreSQL Limitless DB shard-group endpoint.

[^4]: AWS does not support Blue/Green deployments on Aurora global databases.

[^5]: This plugin is designed to only help with Aurora cluster writer endpoints which this is not.

[^6]: The `verifyInitialConnectionRole` parameter is strongly recommended to remain `true` (default) for these endpoint types. The actual host role may differ from the assumed role, and disabling verification can cause incorrect read/write splitting behavior. See [Initial Connection Role Verification](./using-plugins/UsingTheReadWriteSplittingPlugin.md#initial-connection-role-verification) for details.

[^7]: The initial connection plugin is incompatible with the Aurora custom endpoint URL type.

[^8]: The initial connection plugin needs a cluster endpoint to resolve; this endpoint points at a single host or has no discoverable topology.

[^9]: Host monitoring probes a specific database instance. An RDS Proxy endpoint hides the individual instances behind the proxy, and a Limitless DB shard-group endpoint exposes no per-instance topology, so there is no single node for the plugin to monitor.

[^10]: The plugin disables failover on RDS Proxy endpoints; the proxy performs its own failover.

[^11]: This plugin does not operate on the Aurora Limitless DB shard-group endpoint; Limitless shard groups manage their own routing.

[^12]: RDS Proxy transparently re-routes each request to an instance it selects and hides the cluster topology, so topology-based read/write splitting cannot reliably route reads to a reader and writes to the writer. Connect through the proxy's own read/write endpoints instead through a Simple Read/Write Splitting variant.

[^13]: The fastest-response strategy measures and compares response times across multiple reader instances; a Limitless DB shard-group endpoint exposes no such instance list to choose from.

[^14]: AWS Blue/Green deployments are not available for RDS Multi-AZ DB clusters.

[^15]: Blue/Green is not supported on the Aurora Limitless DB shard-group endpoint.

[^16]: Host monitoring needs a resolvable RDS/Aurora instance topology; an IP address or custom domain provides none, so monitoring does not operate here.

[^17]: Set `clusterInstanceHostPattern` so the driver can build instance endpoints from the topology, because an IP address or custom domain cannot be pattern-matched to instance hostnames on its own. See [Failover Configuration Guide](./using-plugins/UsingTheFailoverPlugin.md#failover-parameters).

[^18]: An IP address or custom domain does not encode the RDS/Aurora hostname or region, so supply it explicitly:
 - `iam`, `okta`, `federatedAuth`: set `iamHost` (and `iamRegion` if the region cannot be inferred) so the IAM token is generated
for the correct host
 - `awsSecretsManager`, `awsSecretsManager2`: set `secretsManagerRegion`

[^19]: Set `clusterInstanceHostPattern` so the Blue/Green plugin can associate the IP address with the deployment topology. See [Blue/Green Deployment Plugin](./using-plugins/UsingTheBlueGreenPlugin.md).

[^20]: The Blue/Green plugin resolves the deployment from a recognizable RDS endpoint; it cannot follow a switchover behind a custom domain name.
